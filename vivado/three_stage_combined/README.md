# three_stage_combined — combined three-core overlay (2026-08-11)

Vivado 2025.2, xc7z020clg400-1. Block design `tme_bd`: `binarize_core_0`
(TermCount:hls:binarize_core:2.0), `patch_extract_core_0`
(TermCount:hls:patch_extract_core:0.1), `tme_top_0`
(TermCount:hls:tme_top:0.2), five AXI DMAs (`axi_dma_binarize` with 26-bit
transfer length for the 63,078,400-byte full page, `dma_pe_data`,
`dma_pe_meta`, `axi_dma_patch`, `axi_dma_templ`), memory ports
HP0=matcher, HP1=binarizer, HP2=patch extract.

- `bd/` — the block-design export Tcl the build was reconstructed from
  (`tme_bd_post_patch_extract_pre_synth_20260810_224708.tcl`).
- `scripts/` — reconstruction and signoff Tcl: `add_patch_extract_stage.tcl`
  (BD surgery that added the extractor stage), `audit_fresh_open.tcl`,
  `repair_rebuild_export.tcl` (rebuild + export path), and
  `run_postextract_signoff.tcl` (route + report signoff).
- `board_bundle/` — the deployable pair: `three_stage_combined.bit` +
  matching `three_stage_combined.hwh`, with `BUILD_INFO.txt` recording
  SHA-256 of both, of the BD, of the project, and of the routed checkpoint.

The routed checkpoint (`three_stage_combined_routed.dcp`, ~28 MB) is NOT
committed; `BUILD_INFO.txt` carries its SHA-256
(`1B34B864BB54091B6CABA07A4751E66C541DAA472C426542FCCA944947B6DD54`) so a
local copy can be verified against exactly this build.

This bundle is the exception to the repository's "no Vivado outputs" policy:
it is the release artifact the board runbook (`sw/BOARD_RUNBOOK.md`)
deploys, kept so the silicon results are reproducible from the repo alone.
Everything else generated by Vivado stays excluded.

Board timing context: the design is constrained at 20 ns; the board's PL
clock is 31.25 MHz (32 ns). Never quote a WNS without its period.
