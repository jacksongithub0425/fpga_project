# WHAT MAY NOT BE COMMITTED AT ALL: DRAWING IDENTIFIERS
#
# The corpus is 35 confidential drawings.  Their FILENAMES identify them,
# and two tools in this repository had already said so -- the `redact()`
# in tme_trace_capture.py ("a source DRAWING FILENAME is itself
# identifying") and page_labels() in tme_full_search_baseline.py ("must
# not appear in any committable output").  Neither was enforced, and the
# eight B2-PROD commits carried 35 identifiers into 20 tracked files.
#
# THE DECISION, taken before the branch was ever pushed: enforce the rule
# the repository already stated, rather than scope it down to "aggregate
# outputs only".  Scoping it down would have meant weakening those two
# comments and the frozen-detections rule in cpu_baseline_snapshot.py,
# which is a larger change than fixing the leak.  The eight commits were
# rewritten; nothing had reached any remote.  See logs/REDACTION_NOTE.md.
#
# THE RULE.  Committable output names pages by LABEL:
#
#     doc_001 .. doc_035     one per file
#     page_001 .. page_036   one per page
#
# doc_NNN and page_NNN are NOT interchangeable and do NOT line up:
# doc_001 spans two pages, so every later document is offset by one and
# all 34 of them diverge. `--map` is the crosswalk and is LOCAL ONLY.
#
# sw/corpus_labels.py owns the label space and carries the gate:
#
#     python sw/corpus_labels.py --check <paths>   # non-zero on a leak
#
# TWO PASSES, and they fail in different directions:
#
#   structural  matches the SHAPE of a drawing number. Needs no corpus,
#               so it runs from a bare clone. Cannot see a FRAGMENT.
#   fragment    matches the distinctive middle of each corpus number, by
#               value, derived from the corpus at scan time. Needs the
#               corpus; without one the gate exits non-zero and names the
#               pass it could not run rather than reporting a clean scan.
#
# Do not widen the structural regex to cover fragments. It was widened
# once and matched `14-versus-16` in docs/pl_interface_contract.md, in a
# file present in every commit including the pushed base.
#
# BEFORE PUSHING, the range matters and not the tip -- a push publishes
# history, and both findings here were in commits behind HEAD:
#
#     git config core.hooksPath .githooks     # once; hooks are not cloned
#
# .githooks/pre-push runs sw/pre_push_scan.py over every ref git offers on
# stdin: tree contents, pathnames AND commit messages, for every commit in
# the range. `python sw/pre_push_scan.py --range A..B` is the same scan by
# hand.
#
# NEVER COMMITTABLE, and no CONTENT scan can catch it:
#
#     *.private.json
#
# `tme_backend_parity.py --private-json` writes per-detection geometry --
# boxes and scores read off the drawings. It is already label-keyed, so
# nothing in it is shaped like a drawing number and no scan will flag it.
# The NAME is the only signal, so it is enforced in two places: the tool
# refuses any other name, and pre_push_scan.py refuses a push whose
# history contains one. It is not in .gitignore yet -- that file carries
# unrelated uncommitted work -- and ignoring it locally would say nothing
# about what a commit already holds, which is why the pre-push check is
# the load-bearing one. Add `*.private.json` to .gitignore anyway when
# that work lands.
#
# The scan covers ref NAMES too, local and remote: a branch is published
# as surely as a blob, and nothing stops one being named after a drawing.
