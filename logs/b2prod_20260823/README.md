## Provenance of the `.as_run` snapshots — NOT uniform

Every `.as_run` here is the file that was uploaded to the board. They differ
in whether that is **attested** or merely **asserted**, and a reader looking
at seven files of the same shape would otherwise assume they are alike.

**Read back from the board** with `sha256sum` after upload and before the
run, and the committed file matches:

```
aa248372d210bd8d77833994812f187c7a588f45f00b9f0dce3aa85cd99f92bc  09_step2_fitz_probe.sh.as_run
7815fe79b33077ff2dece220db04887a014e28752dc83148c0f359f0f4d5cce0  09_step2_fitz_probe_env.py.as_run
658cabd87f7cf35715ed513b5507e8487ea08080a5ab57159c33ea85fd688967  09_step2_fitz_probe_func.py.as_run
cf0806cf2b9ca6129707a9908bb191bf6bbb737cb498d522dc9049b6517e2f41  09_step2_fitz_probe2.sh.as_run
522cf788b298a8ea2d1739a0064edd66798a96a633b03bbf982f13c0b404b484  07_pynq_alias_probe.py.as_run
```

**Not read back.** Uploaded and run in one command with no `sha256sum` step,
so what is committed is the local file the uploader sent — not a
board-confirmed digest:

```
08_samples_mv_probe.py.as_run
08_samples_mv_run.sh.as_run
```

The board copies are gone, so this cannot be repaired after the fact, only
re-run. It does not weaken `08_samples_mv.txt` itself — that transcript
prints the interpreter's own answers — but the *script* behind it is
attested one step less well than the other five, and that is worth knowing
before either is quoted.

`.gitattributes` marks this whole tree `-text` so a checkout cannot rewrite
the bytes these digests describe.
